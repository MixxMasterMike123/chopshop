## 1. Decisions already taken (do not reopen; argue in the report if one is wrong)

Design §0 A1–A14 and the Codex-marked items. The ones a builder trips on:

- **Rates:** 15 % commission (`commission_bp 1500`), 10 % buyer discount (`discount_bp 1000`).
- **Representation:** an affiliate hit returns `discountCodeId = affiliate_id` with `authority = 'affiliate'`; holds and burns run only for `authority = 'campaign'` (design §2.2).
- **Accrual from frozen facts only** (design §4.1); self-referral decided and frozen at quote (§4.3).
- **Reversal** in `orderEffectStatements` (ref = transition id, cumulative, ± on failure) and in `applyDisputeFact` for `lost` (§4.2). Nothing in `cancelOrder`.
- **Payout** manual rail only (`rail = 'manual'`), reserve-first (§6). No Stripe call anywhere in CP13.
- **Identity:** `identity_access` rebuilt with `'affiliate'`; one credential, one `tenant_memberships` row `role='affiliate'` per shop; `not_addable` both ways (§1).
- **Clicks:** the normalised `?ref=` code rides on the `GET /v1/seo` call the web Worker already makes per page landing; the API counts under its own `ctx.waitUntil`, rate-limited per hashed visitor (§2.1). No new route, no web-Worker `ExecutionContext` change.
- **Route prefixes:** storefront = `POST /v1/affiliate-applications`, `GET /v1/affiliate-terms` (flat, hostname tenant); portal = `/v1/affiliate/*` (admin host, `X-Shop-Id`); admin = `/v1/admin/affiliates/*`.
- **Reversal rows carry either sign** (a restoration after `succeeded → failed` is a positive `reversal`); `ref` = the refund TRANSITION id; a lost dispute forces the full reversal (§4.2).
- **0059's `discount_authority`:** added without the iff CHECK, backfilled `'campaign'`, then the coherence TRIGGERS; the burn re-gated on `IS NOT 'affiliate'` (§2.3).
- **No hard delete of an affiliate**; balances per (affiliate, currency); an unaccepted affiliate identity may be converted by a tenant-admin/platform invite (§1.3).
