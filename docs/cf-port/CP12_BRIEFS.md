## The contract both units build to (fixed here so F2 and F3 run in parallel)

- `PrinterModel` gains optional `kind: "garment" | "flat"` (absent = garment), `requiredSlots?`, `prodigiPrintArea?: string`, `attributes?: Record<string,string>` (≤ 12 keys, values ≤ 64 chars), and `front.px?: { w, h }` (the printer's exact pixel area). The platform printer view and the catalogue apply carry them through; the TENANT printer view (`/v1/admin/pod/printers`, the allowlist projection) exposes `kind`, `garment`, the `front` area (mm + px) and nothing of attributes/costs.
- A flat model has exactly one slot, `front`; its SKU key's "colour" part is the finish (`white-frame`) and its size part the sheet (`11x14`).
- The studio asks the existing quote route per SKU as today; the "Inköp" per size is what it shows.
- The print pipeline: for a flat line the canvas is the model's `front.px` exactly (no offset, no garment frame), the motif placed by the studio's `fit: "cover" | "contain"` + `background` (hex) frozen in the mapping's placement (the mapping already freezes placement per slot: add `fit` and `background` as optional keys there; absent = today's garment behaviour).
- The wire: `assets[0].printArea = model.prodigiPrintArea ?? "front"`, `attributes = { ...model.attributes }` merged with the key's `{color,size}` ONLY for garment models (a flat model sends the fixed attributes only), `sizing: "fitPrintArea"`.
